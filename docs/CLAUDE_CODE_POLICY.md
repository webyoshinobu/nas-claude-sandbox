# Claude Code 利用ルール

## 目的

本サンドボックス環境におけるClaude Codeの役割を明確にし、意図しないコード変更・リポジトリ操作を技術的・運用的に防止する。

## 許可される用途

Claude Codeは以下の用途にのみ使用する。

- コードに関する**相談**(設計方針、実装方法の検討など)
- **原因調査**(エラー・不具合の原因特定、ログの読み解き)
- **ソース解析**(既存コードの構造・処理内容の説明、リファクタリング案の提示など、あくまで「提案」にとどめる)

## 禁止される用途

- ファイルの**書き換え・新規作成・削除**
- `git add` / `git commit` / `git push` などの**Gitリポジトリ操作**
- 上記に類する、リポジトリやファイルシステムの状態を変更する一切の操作

## 技術的な担保

上記ルールは運用上の申し合わせだけでなく、以下の技術的な制約によって裏付けられている。

| 項目 | 内容 |
|---|---|
| マウント方式 | NFS経由、`:ro`(read-only)でコンテナにバインドマウント |
| 効果 | コンテナ内から`/workspace`(=NAS上の`projects`フォルダ)への書き込みは物理的に不可能 |
| 動作確認 | コンテナ内で`touch test.txt`を実行し、`Read-only file system`エラーが出ることを確認済み |

これにより、Claude Codeにどのような指示を与えても、意図的・非意図的を問わずファイルの書き換えは成立しない。

## 起動コマンド(参考)

```bash
sudo docker run -it --rm -v /share/projects:/workspace:ro claude-code-sandbox
```

`:ro`オプションを外して起動しないことを、本ルールの絶対条件とする。

## 実際にコードを変更する場合の運用

Claude Codeとの相談・調査結果をもとにコードを変更する場合は、以下のいずれかで**人間が**作業を行う。

- PC上のIntelliJ / VS Code(NAS上の`projects`フォルダをSMB経由でネットワークドライブ/共有フォルダとして開いて編集)
- PC上のSourceTree(commit / push / pull)

## 改訂

本ルールを変更する場合は、変更内容と理由をこのファイルに追記し、Gitリポジトリにコミットして履歴を残す。

| 日付 | 内容 |
|---|---|
| 初版 | 用途を相談・原因調査・ソース解析に限定し、書き換え・コミット・push禁止を明文化 |
